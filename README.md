# RuReviews, тональность отзывов: TF-IDF+LogReg baseline, fine-tuned BERT

Классификация тональности отзыва на женскую одежду/аксессуары (3 класса:
negative / neautral / positive) на
данных [RuReviews](https://github.com/sismetanin/rureviews). Сравниваются
классический baseline (TF-IDF + логистическая регрессия) и дообученный
`DeepPavlov/rubert-base-cased`.

## Результат

| Модель | test accuracy | test macro F1 |
|---|---|---|
| TF-IDF + LogReg (baseline) | 0.7571 | 0.7583 |
| **BERT (fine-tuned)** | **0.7700** | **0.7741** |

**Прирост BERT над baseline небольшой** 

это можно объяснить тем, что короткие отзывы на маркетплейсе часто выражают тональность
явными словами ("ужасно", "рекомендую"), которые TF-IDF, считая
только частоты слов и биграмм, ловит очень хорошо.
Контекстное преимущество self-attention проявляется сильнее на
отрицаниях и смешанной тональности внутри одного текста, а здесь прямые тексты

## Задача и данные

90 000 отзывов, сбалансировано по 30 000 на класс. Датасет читается
напрямую по URL с GitHub

**Деталь о происхождении меток** 

Метки получены автоматически из исходной 5-балльной оценки товара, свернутой в 3 класса, а не через
ручную разметку тональности текста человеком, что повлияло на
интерпретацию результатов (см. анализ ошибок ниже), потому что часть измеренных
ошибок модели это шум разметки, а не проблема BERT

## Модель

`DeepPavlov/rubert-base-cased` — encoder-only трансформер (bidirectional
self-attention), 177.9M параметров

Классификация через представление служебного токена `[CLS]`, который через self-attention агрегирует
информацию всего отзыва, плюс небольшая классификационная голова поверх.
**Full fine-tuning**, обновляются все слои

## Confusion matrix 

Доминирующая ошибка это реальные **negative** предсказываются как
**neautral** (1025 случаев), следом
positive - neautral (489) и neautral - negative (375). 

Recall по классам: neautral 82.9%, positive 83.0%, но negative заметно ниже, 65.2%.

Соседние классы (особенно negative) утягивает в сторону neautral, то есть neautral работает как магнит для пограничных выраженных отзывов

## Анализ ошибок

Среди прочитанных вручную примеров минимум 2 из 5
выглядят как реальный шум в автоматической разметке — например, отзыв
*«Товар не соответствует фото. Качество ужасное»* размечен как `neautral`,
хотя текст негативный и BERT предсказал `negative`

Остальные случаи это уже пограничные сложности задачи; смешанная
тональность внутри одного отзыва вроде *«Доставка долгая, а так всё
хорошо»*).

**Длина отзыва не связана с точностью** 

Распределение длины (в словах) практически идентично и для верных, и для ошибочных предсказаний

## Ограничения

Метрики без кросс-валидации, верхняя граница качества ограничена шумностью самой разметки

## Что можно улучшить дальше

- Отдельная стратегия для границы negative/neautral, можно попробовать
  asymmetric class weights или отдельный бинарный классификатор "явный
  негатив vs остальное" как первый фильтр
- Ручная перепроверка большей выборки (не 5, а 50-100 примеров) ошибок —
  для более строгой оценки доли шума в разметке против настоящих ошибок
  модели
- `rubert-tiny2` для сравнения скорости/качества с более компактной
  моделью
- Больший `MAX_LENGTH` для самых длинных отзывов
